# Mode-Based Work + Pause Stack + Intake

I operate in a small set of MODES, not tasks. Context switching is expensive; switching modes is gated. 
An intake list and backlog are utilized to redirect distracting or intrusive thoughts to a safe-keeping space.
I don't like strict schedules; but my busy lifestyle with fragmented projects and activities 
will benefit from improved focus.

## Mental Model
- **Pomodoro (Round)**: 30 minutes, atomic focus, no switching.
- **Block**: 1–4 Pomodoros on one ACTIVE card.
- **ACTIVE card**: Intent (what this work session is about).
- **PAUSED STACK**: Resumable, inactive threads.
- **BACKLOG**: Cold storage, not resumable.
- **DONE / CONTEXT**: Read-only history of last NEXT states.
- **PARKING LOT**: (intake area.) `idea | urgency | mode` Linked to Trello "Inbox"


Core idea:
> Pomodoros spend effort. ACTIVE cards hold intent. Blocks protect depth. 
> This is more powerful than Pomodoro alone because it reduces cognitive rehydration cost.

Parking lot:
> Rule: any intrusive thought or "nice to have" → dump it, don’t act on it.
> Your brain keeps switching because it’s afraid of forgetting.
> Review only during breaks or end-of-day sweep... this reassures your mind that nothing is lost, so it lets go.

---

## Modes
- **Build**: coding, architecture, deep technical design
- **Operate**: sysadmin, tickets, cleanup, admin
- **Lead**: strategy, company board work, investments, advising, writing
- **Life**: health, relationships, entertainment, travel, logistics

Max **1 ACTIVE card per mode**.

---

## Rules for Days With Only 1–2 Pomodoros Available

1. Do not start a Block unless you can do at least 2 Pomodoros.
2. If you have only 1 Pomodoro:
   - Choose Operate or light Build/Lead tasks.
   - Prefer tasks safe to abandon mid-progress.
3. Small tasks = 1 Pomodoro max.
   - Quick emails
   - Calls
   - Scheduling
   - Ticket grooming
4. Never split one Pomodoro across multiple cards.
5. If interrupted mid-round:
   - Abort it.
   - Restart fresh later using NEXT.

Heuristic:
> If interruption would annoy you → wait for a Block.
> If interruption would be fine → safe for 1 Pomodoro.

## Daily Process Checklist

- [ ] Identify today's ACTIVE modes (max 3)
- [ ] Select ONE ACTIVE card per mode
- [ ] Confirm PAUSED STACK ≤ 6 cards total
- [ ] Do ROUTINES (dashboards, tickets, fixed items)
- [ ] Start Pomodoro (Round) with clear NEXT
- [ ] No switching during round
- [ ] End round → update NEXT or move card
- [ ] Capture new ideas in PARKING LOT only
- [ ] Normalize board (ACTIVE, PAUSED STACK, BACKLOG)
- [ ] Run Daily Close Ritual

---

## Daily Close Ritual (15–25 min)

1. Update ACTIVE cards to reflect real progress
2. Archive completed cards
3. Clean up files, tabs, recent email
4. Normalize lists:
   - ACTIVE ≤ 2–3 cards
   - PAUSED STACK ≤ 6 cards
5. Rewrite NEXT for tomorrow’s ACTIVE cards
6. Stop

> This ritual replaces rumination with closure.

---

## Non-Negotiables
- Email is Operate work.
- Long emails become cards.
- Cleanup cards are temporary, one-block only.
- DONE / CONTEXT is read-only.



## Notes

### How Time Boxes Fit In (without fixed schedules)

Time boxes don’t choose what you do — they choose **when switching is allowed**.

#### New framing

- Pomodoro = **no switching allowed**
- End of time box = **the only legal switch point**

At the end of a block you must choose:
1. Continue same thread (no switch)
2. Switch threads **within same mode** (pop from stack)
3. Switch modes (only if time box boundary allows it)

This makes switching _explicit and gated_, not reactive.


### Mode-Based Scheduling Without Fixed Times

You don’t need a fixed daily schedule — you need **mode quotas**, not clocks.

#### Example (flexible, non-repeating)

- Today requires:
  - 3 Build blocks
  - 1 Operate block
  - 1 Lead block
- Order is free
- Timing is free
- Once a mode’s quota is hit, it’s closed unless urgent

This satisfies:

- Your dislike of rigid schedules
- Your need for structure-
- Your tendency to avoid low-priority blocks


### The “Hard Stop Demotion” Ritual

This is the keystone habit.

At the end of a block:

1. Decide: **Is this thread still ACTIVE for this mode?**
2. If yes → update the one-sentence continuation
3. If no → demote it to the stack or backlog
4. Confirm there is only **one ACTIVE continuation**

This takes ~30 seconds and prevents mental thrash.

### Why This Works for High-Context Brains
- externalizes working memory
- caps open loops
- preserves psychological safety (“nothing is lost”) while adding guardrails
- allows depth without rigidity
